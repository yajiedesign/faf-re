# The distance oracle and the symbolic tracer

These are the instruments the `DistSegment3Segment3<float>::GetSquared`
transcription was made with.  They live here because they are the evidence,
not a scratch script.

| file | what it is |
|---|---|
| `x87hw32.c` | The x87 register-form semantics, **measured on the hardware**: raw encodings executed in `PAGE_EXECUTE_READWRITE` memory with a known six-register file, dumping the top four registers.  This is the ground truth the simulator's decode was checked against. |
| `sim.py` | The x87 simulator for the retail's `GetSquared` (retail `0x00A7E660`..`0x00A7EE5C`).  It decodes the retail's instructions and executes them on a modelled register file, at either 24- or 53-bit significands (`SIMPREC=53`).  It reproduces the retail's `fSqrDist` **bit for bit on 400 of 400 sampled draws** when the register file is 53 bits and the probe's draws are taken under the rows' control word (`0x007F`). |
| `simrun.py` | Drives `sim.py` over `simd.txt` and compares with the retail's values.  `simd.txt` is the 400-draw sample the probe produced (`WMDIFF_PROBE_S3S3=400,5EED2007,0`); its `retail` column is the retail's own output, taken under `0x007F`. |
| `symtrace.py` | The symbolic post-processor over the simulator's trace: every register carries a value *and* an expression, so the block's arithmetic comes out as an expression rather than a number.  It is checked against the simulator step for step (every live register value, before every instruction) and end to end (the expression it ends with evaluates to the retail's bits). |
| `symrun.py` | Drives the tracer and prints the traced expression for a draw, in the retail's own names: `fA01`, `fB0`, `fB1`, `fC`, `fDet`, `fS0`, `fS1`, `s0.d.y`, `s1.ext`, and `r32(...)` for a spill to a 32-bit slot. |

## Running them

```
set SIMPREC=53
python simrun.py simd.txt              # the simulator against the retail
python symrun.py 223 226 260           # the traced expression for a draw
```

`simd.txt` is regenerated by the harness:

```
WMDIFF_PROBE_S3S3=400,5EED2007,0 build/wmdiff_release.exe --iters 400 > probe.txt
```

The probe must run under the rows' control word (`0x007F`); `main.cpp`'s
`SetFpEnv` sets it for the rows, and `RunSegmentSegmentProbe` sets it for
itself (setting it in `main.cpp` before the probe call does **not** stick -
see the main README).

The 64-bit constant the interior loads (`2.0` at `0x00D71CD8`) is modelled in
the simulator's memory; the tracer reads it from there.
