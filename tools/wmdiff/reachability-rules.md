# 可达性判定规范（配对工作的第一步）

本文件规定：**在给任何函数/类写比对项之前，如何判定"重建版真的会执行它"**。
判定分三轮，**由粗到细**，每一轮都能否掉一批候选；**只有通过第三轮的才进入配对队列**。

> 这套规范是踩出来的，不是想出来的。起因：`IntrBox3Sphere3<double>` 被"看起来在用"误导过两次
> （`grep` 命中、`static_assert` 被显式实例化触发），而 `ConvexHull3<double>` 更隐蔽 ——
> 它**确实被链接**（`Foundation.lib(Wm3ContBox3.obj)` 引用它），但 `src/` **永远到不了**
> 那个调用点。判定的粒度必须是"**实际会执行**"，不是"被链接"。

---

## 第 0 轮：先量"这个实例化有没有被链接"

**目的**：用一次构建把 140 个候选砍到个位数。**这一轮只做初筛，结论不可直接采用。**

做法：把某个精度的**全部** `template WM3_ITEM class X<T>;` 一起注释掉，重新构建
`main.vcxproj`：

* **链接通过** ⇒ 整个精度没有任何引用 ⇒ **出局**（这一轮最省时，一次几分钟）；
* **链接失败** ⇒ 未解析符号**直接点名**被引用的类与成员，且错误行**带 `.obj` 名**。

**误报来源（必须知道）**：

1. **显式实例化**本身就能让 `static_assert` 之类的探针触发 ⇒ 探针法会假阳性；
2. **`Foundation.lib` 内部互相调用**会让一个类"被链接"，哪怕 `src/` 根本调不到
   （`ConvexHull3<double>` 就是这样：`Wm3ContBox3.cpp:220` 的 `ContMinBox` 调它，
   而 `src/` 只调 `ContAlignedBox`，两条路在 `ContAlignedBox` 里就分开了）；
3. `grep` 类名会命中头文件、注释、显式实例化 ⇒ **不能作为判据**。

⇒ ⇒ **第 0 轮只能回答"整个精度有没有人引用"**。要回答"这个类/成员会不会执行"，
必须继续第 1、2 轮。

---

## 第 1 轮：逐调用点看**实参类型**

**目的**：模板类的实例化由**调用处的实参类型**决定，所以一个 `Wm3::ContAlignedBox(...)` 调用
只实例化它被喂的那个精度的版本。

做法：把第 0 轮点名的每个 `.obj` 打开，找到**调用点那一行源码**，读**实参的静态类型**：

```cpp
Wm3::Vector3f vertices[8];
const Wm3::Box3f aligned = Wm3::ContAlignedBox(8, vertices);   // → float 实例化，只此一个
```

* 实参是 `Vector3f` / `Box3f` / `float` ⇒ **只实例化 `float`**；`double` 一律不成立；
* 实参是 `Vector3d` / `Box3d` / `double` ⇒ 只实例化 `double`；
* 实参是**模板参数 `Real`** ⇒ 由外层的实例化决定，**回到上一层继续追**（这就是第 2 轮）。

⇒ ⇒ 这一步抓的是"**看起来用了 double，其实调用点给的是 float**"这一类误报。

---

## 第 2 轮：向上追调用链，直到 `src/`

**目的**：`Foundation` 内部的调用不算数。**要一路追到 `src/` 里某个真正会被引擎执行的入口**，
或者追到"没有上级"（那就出局）。

做法：对每个候选，建立一条链，并**逐级确认实参类型**：

```
src/sdk/....cpp:NN            ← 必须是 src/ 的代码
   └─ Wm3::Foo<float>(...)    ← 实参 float
        └─ Wm3::Bar<float>(...)   ← Foundation 内部，实参是 Real=float
             └─ Wm3::Baz<float>(...)
```

**判据**：

| 链的终点 | 结论 |
|---|---|
| 到达 `src/` 的某个函数 | **可达** ⇒ 进配对队列 |
| 只到 `Foundation` 的某个**没人调**的函数 | **不可达** ⇒ 出局（记为 `linked-but-unreachable`）|
| 链在某处断了（找不到调用者）| **不可达**，但要注明"链断在 X"，便于复核 |

**`double` 要特别审慎。** 到目前为止，**没有一处 `src/` 的调用点给出 `double` 实参**：
`ConvexHull3<double>` 的调用者 `ContMinBox` 自己就是 `Real` 模板，而 `src/` 只调
`ContAlignedBox`（其 `float` 实例化里**不走** `ContMinBox`）。所以在第 1 轮看到
"实参是 `Real`"时，**默认假设是 `float`**，除非能指出 `src/` 里给出 `double` 实参的那一行。

---

## 第 3 轮：读**上下文**，不要只看一行

**目的**：调用点那一行常常不足以判断。要读**上下若干行**（至少整个函数体），确认：

* 实参的**声明**在哪、类型是什么（`Vector3f` 还是 `Vector3d`）；
* 有没有 `if constexpr` / 模板分派让另一精度被排除；
* 那个函数**自己**是不是可达的（回到第 2 轮）；
* 有没有**别名**（`typedef` / `using`）把 `float` 写成别的名字。

⇒ ⇒ 实例：`Wm3AxisAlignedBox3FafExtras.cpp:26` 那行只看函数名会以为"通用"，读了上下文才看到
`Wm3::Box3f box`、`Wm3::Vector3f vertices[8]` ⇒ ⇒ **只有 float** ✓

---

## 结论的三种状态（写进 `reachable.md`）

| 状态 | 含义 | 允许进入配对队列 |
|---|---|---|
| `executed` | 第 2 轮追到 `src/`，且第 1/3 轮确认了精度 | **是** |
| `linked-but-unreachable` | 被链接，但 `src/` 到不了 | **否**（记录下来，不排期）|
| `not-linked` | 第 0 轮就出局 | **否**（不必记录到比对项级）|

---

## 执行者

**这套判定必须由 sub agent 执行**，不能由主线顺手做：它要开 `.obj`、逐级追调用链、读
上下文若干行，是一次独立的调查工作。派活时说清楚：

1. 目标是**判定**，不是写比对项；
2. 对每个候选给**三轮结论 + 那条链**（`src/...:NN → Foundation/...:NN → ...`）；
3. `double` 一律按"默认可疑"处理，除非指出 `src/` 里给 `double` 实参的那一行；
4. 结论写回 `reachable.md` 的 `engine uses` 列（三种状态）；
5. **不许改源码**，这一轮只查不改。
